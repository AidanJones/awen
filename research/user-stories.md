# Awen feature inventory and user stories

Reviewed 8 November 2026, task `awen-ovo`. This inventory covers the shipped
reader, personal explorer, listening-review templates and development reports.
It describes current capabilities, not every proposed backlog experiment.
See the [flow review](usability-review.md) for findings, changes and limitations.

## Read and control the experience

| ID | User story | Entry / acceptance |
|---|---|---|
| R01 | As a reader, I want to choose a complete book so I can settle into a story. | Four-book shelf; editions, chapter order and stable paragraph IDs remain intact. |
| R02 | As a returning reader, I want to continue where I left off without setting everything up again. | Continue reading names the selected book/paragraph; per-book position and compatible score checkpoints restore; sound still needs a gesture. |
| R03 | As a reader, I want to move one paragraph at a time while the music keeps its place. | Previous/Next, keyboard arrows/Space and persistent transport; navigation preserves the running graph/clock. |
| R04 | As a reader, I want to jump to a chapter or paragraph, or deliberately restart. | Chapter selector, numbered jump and Restart book retain their existing semantics; restart returns to the seeded beginning. |
| R05 | As a reader, I want comfortable text and fewer distractions. | Aa/Reading preferences adjusts size, line spacing and width; Night reading and Focus mode remain available. |
| R06 | As a focused/mobile reader, I want to pause or mute without leaving the text. | Sticky Start/Pause, Mute, paired paragraph buttons and position remain visible in focus mode; Sound settings reveals the sidebar. |
| R07 | As a reader, I want to know where the text came from. | Edition source/licence links and Edition notes retain revision, attribution and colophon information. |

## Start, understand and route sound

| ID | User story | Entry / acceptance |
|---|---|---|
| A01 | As a first-time listener, I want to start gently and stop immediately. | Main/compact transport share the same Start/Pause/Mute implementation; Escape and gallery mute release sound. No autoplay on load. |
| A02 | As a listener, I want level and density controls without learning the engine. | Volume, Continuous background and Mix the layers retain independent controls; browser samples still use the shared limiter. |
| A03 | As a listener, I want to distinguish a quiet passage from a broken output. | Test browser sound, browser waveform/signal and playback status distinguish measured browser signal from unmetered hardware audio. |
| A04 | As a reader, I want the music to follow the story or stay neutral. | Follow the story versus Steady ambience; local 28-label dictionary, scoped evidence and six coarse scenes retain smoothing/dwell/phrase continuity. |
| A05 | As a returning listener, I want a reproducible interpretation. | Score seed, new interpretation, active/queued seed and compatible checkpoints retain per-book identity and phrase-boundary changes. |
| A06 | As an FM1 owner, I want to hear notes generated by the synth rather than mistake laptop audio for its patch. | Where should the music play? explicitly selects Browser, External MIDI only or Both. Unarmed hardware selection blocks Start and reveals setup. |
| A07 | As an FM1 owner, I want a guided connection and a useful test. | FM1 setup → Find → select device/channel → Enable → Test MIDI note → Start. Browser test is named separately. |
| A08 | As a hardware listener, I want to choose what is sent and how notes are bounded. | Harmony/full score/foreground, selected channel and velocity cap stay in MIDI controls. Hardware patch/physical volume remain on the synth. |
| A09 | As a listener, I want failures to stop cleanly and tell me how to recover. | Pause/mute/panic, disconnect, hidden page and interrupted context release owned notes; reconnect needs explicit enable. No unintended laptop fallback when external output is requested. |

## Find and refine musical directions

| ID | User story | Entry / acceptance |
|---|---|---|
| M01 | As a listener, I want a different instrumental colour without restarting the score. | Browser sound palette retains ten procedural palettes; external-only mode labels it as browser-preview colour. |
| M02 | As a listener, I want broad starting recipes before tweaking small numbers. | Explore music → Compare musical starting points offers authored recipes and the current favourite. |
| M03 | As a listener, I want classical-inspired patterns with a controllable development policy. | Classical controls retain nine homes, fixed/expression/chapter modes, source notes and compare/apply actions. |
| M04 | As a reader, I want to suggest my own interpretation of a scene. | Explore → Interpret the scene opens existing 28-label, scope/note, chord-retention and musical-alternative controls; interpretation stays separate from preference. |
| M05 | As a listener, I want to try different chords and dramatic directions. | Chord gallery retains genre/function/family/tonic, six choices, manual harmony priority and a return to starting-point harmony. |
| M06 | As a curious musician, I want to edit a bounded score language. | Score language editor remains in exploration with presets, validation, apply/compare/clear. No required build or cloud model. |
| M07 | As a listener, I want to compare variations fairly before committing. | Six-card gallery retains matched context, one playing preview, duration, attenuation-only balancing, cancellation and limiter. Header Return to reading is always available. |
| M08 | As a listener, I want to keep favourites and explore from one or several parents. | Keep, Pin/name, parent checkboxes, nearby/wide and foreground/background scopes, new batch and temporary batch undo remain available. |
| M09 | As a listener, I want to recover from a choice I regret. | Return/cancel restores cursor and pauses; Undo last kept choice restores prior preference. Pins/history remain bounded and persistent as before. |
| M10 | As an explorer, I want nine diverse directions rather than only a nearby six-card mutation. | Optional personal explorer retains broad/Bach/classical nine-card sets, passage, seed, excerpt, parents, evolving rounds and previous/reset actions. |
| M11 | As an explorer, I want selection to have a clear meaning. | Select for next round selects up to three parents; it does not claim to adopt music in the reader. Selected cards and generation actions remain visible. |
| M12 | As an explorer, I want to carry a direction into the reader with its actual browser instruments. | Download reader profile → reader Backups → Import music profile. New explorer exports explicitly include a validated palette; old profiles preserve their existing behaviour. |

## Feedback, saving and recovery

| ID | User story | Entry / acceptance |
|---|---|---|
| F01 | As a listener, I want to say what works without constant prompts. | Give feedback opens optional enjoyment, passage-fit and reading-help scales, complaint tags and notes. Saving changes no music. |
| F02 | As a listener, I want my rating attached to what I was hearing. | Capture freezes paragraph, active/pending genome, scheduler state and browser/MIDI route; optional setup note can name an FM1 patch. |
| F03 | As a listener, I want unknown answers to remain unknown. | Unanswered axes remain null; tags, candidate selection and personal story labels are not automatically converted into ratings. |
| B01 | As a returning listener, I want browser saving and a file backup to be clearly different. | Saved browser state and profile-file freshness retain separate status; Backups explicitly describes its scope. |
| B02 | As a listener, I want a music-profile file for favourites and kept directions. | Backups exposes download/import and file-picker update actions; write cancellation/failure and download fallback retain their protections. |
| B03 | As a listener, I want feedback and story interpretations backed up without mixing them with music profiles. | Backups has distinct profile, feedback and interpretation sections; feedback merge validates and rejects conflicts before mutation. |
| B04 | As an explorer, I want to retain all rounds rather than only one selected sound. | Exploration backup/export/restore is explicitly different from a single reader-profile download. Version/engine compatibility checks remain. |
| B05 | As a listener with blocked/full storage, I want usable recovery rather than silent loss. | Existing storage errors and downloads remain; unreadable feedback is preserved, capacity does not evict records, and backup task errors are surfaced in the hub. |

## Listening review and development

| ID | User story | Entry / acceptance |
|---|---|---|
| S01 | As a listening participant, I want to read, compare A/B and answer in my own time. | Calibration and recurrence templates explain the task, retain passage/context and provide sticky A/B/Stop controls with jump links. |
| S02 | As a participant, I want ratings to remain independent and optional. | Fit/enjoyment/distraction and recurrence where applicable retain ties, unsure, unanswered, confidence, notes and exposure metadata. No forced winner. |
| S03 | As a participant, I want to pause a session and resume it safely. | Packet-specific local storage, silent reload, navigation/filtering, unique rating download and strict backup restore remain available. |
| S04 | As a researcher, I want blind trials without silently changing the original materials. | New templates improve flow; frozen audio/packets, identities, keys and previous responses are not rewritten. Layout QA fixtures are explicitly test-only. |
| D01 | As a developer, I want reproducible small experiments before spending on large processing runs. | Native audio/score fixtures, source hashes, unique journals, bounded budgets, cached results and crash recovery remain development tools. |
| D02 | As a developer, I want to compare scene-fit/aesthetics/score critics without presenting them as validated taste. | CLAP grid, evaluator/MuQ, multi-objective reports and symbolic/Audiobox diagnostics remain separate labelled research pages/reports; no runtime reward adoption. |
| D03 | As a developer, I want sparse reader exports usable as separate future learning targets. | Shared-schema Node/Python import retains ordinal axes, nulls, context, logs and source-bound receipts; training/evaluation remain separate work. |
| D04 | As a maintainer, I want research knowledge and books to be inspectable and versioned. | Dictionary/harmony/classical JSON, source references, book refresh scripts, paper/docs and Beads remain authoring/research resources, not required reader setup. |

## Page boundaries and open gaps

The runnable reader stays one inline HTML file. The optional explorer is a
standalone generated page. `--include-reader` packages an unchanged reader copy
and adds an explicit round-trip link; a reader downloaded on its own never shows
a broken explorer link. Recorded-clip reviews are a separate activity from
reading or adopting music. Diagnostic experiment reports are for developers.

Full session backup (including reading progress and every setting), notebook
rotation/editing, compatible archived comparison replay, arbitrary EPUB import,
mobile device/browser acceptance, long listening sessions and listener-calibrated
personal ranking remain backlog items. The stories above do not promise these
unshipped capabilities or imply that a heuristic walkthrough proves usability.
